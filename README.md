# 🔭 望远镜夜间序列规划台

使用 **Node.js + Express + 原生前端（Canvas）** 实现的夜间观测序列规划与执行复盘工具。

录入观测点纬度/经度、日期、目标赤经赤纬、曝光时长与最低高度，并可绘制地平线遮挡角；
系统按恒星时逐分钟计算每个目标的连续可见窗口，在**跨子午线翻转、窗口重叠、转台换向耗时**
约束下生成不冲突的观测顺序；无法排入的目标会给出具体原因。

生成计划后还可**逐目标录入实际执行记录**（实际开始/结束时间、完成 / 部分完成 / 跳过），
系统自动计算开始/结束偏差、实际曝光分钟数，识别实际区间是否超出该目标的可见窗口，
并在时间轴与结果表中叠加实际区间、高亮越窗/曝光不足记录，汇总完成率与总偏差。

## 一键启动（Docker）

```bash
docker compose up --build
```

启动后访问：**http://localhost:3000**（端口 `3000`）

> 依赖安装（`npm install`）已包含在镜像构建中，示例目标随服务启动自动载入前端。

## 本地运行（可选）

```bash
npm install
npm start          # 访问 http://localhost:3000
```

## 操作说明

1. **观测设置**：填写纬度/经度、日期、最低高度、转台与换向耗时；可选在画布上拖动绘制
   地平线遮挡角（内置平坦/树林/山坡/圆顶预设）。
2. **目标管理**：逐个添加目标（或点「载入示例目标」），赤经支持 `HH:MM:SS` 或十进制小时，
   赤纬支持 `±DD:MM:SS` 或十进制度，逐目标设置曝光时长。
3. 点击 **「生成观测序列」**：时间轴、观测顺序表与未排入原因随即展示。
4. **录入执行记录**（观测中或观测后均可）：在结果区「执行记录与偏差分析」表中逐行
   - 选择状态：**完成 / 部分完成 / 跳过**；
   - 填入**实际开始、实际结束**（地方平时 `HH:MM`，跨日自动处理：≥12:00 为当天晚上、
     <12:00 为次日凌晨；选「跳过」时无需填时间）；
   - 点击该行的 **「提交」**。同一目标重复提交**以后一次记录自动覆盖**；状态改回
     「未记录」再提交可清除该目标的记录。
5. 复盘展示：
   - **时间轴**甘特区分上下两排：上排为计划段（灰段 = 转台/换向），下排为实际段
     （绿 = 完成、橙 = 部分完成、**红框斜纹 = 超出可见窗口的时段**、计划段上的红 ✕ = 跳过，
     虚线框为计划区间残影，便于对比起止偏差）；高度曲线上同样叠加实际区间。
   - **结果表**高亮：红色底 = 实际区间超出可见窗口，橙色底 = 完成但曝光不足，
     绿色左边条 = 已正常记录；偏差列按幅度着色（绿 <3 分 / 橙 <10 分 / 红 ≥10 分）。
   - **汇总条**：完成率（部分完成按 0.5 计，基数为已排入序列的目标数）、总绝对偏差、
     平均偏差、累计实际曝光分钟，以及越窗/欠曝/待录入计数。
6. 重新生成同参数的计划（或刷新页面后再次生成）时，历史执行记录会自动恢复——
   记录按规划参数指纹（`planKey`）+ 目标序号匹配。

> 执行记录保存在服务端内存中（适合单机当晚使用），服务重启后清空；最多保留最近 50 份计划。

## 功能说明

- **观测设置**：纬度/经度、日期、最低高度、转台耗时、换向（子午线翻转）耗时
- **地平线遮挡角**：画布上拖动绘制 0–360° 方位的遮挡轮廓，内置平坦/树林/山坡/圆顶预设
- **目标管理**：赤经支持 `HH:MM:SS` 或十进制小时，赤纬支持 `±DD:MM:SS` 或十进制度，逐目标曝光时长
- **窗口计算**：基于地方恒星时逐分钟判定 `高度 ≥ max(最低高度, 地平线遮挡角)` 的连续窗口，
  并在上中天处切分为「东升侧 / 西落侧」两段（翻转点 ◆）
- **序列调度**：最早窗口截止优先的贪心算法；相邻目标计转台耗时，叉臂换侧计换向耗时，
  单次曝光不跨越翻转点，保证序列互不冲突
- **失败原因**：高度不足 / 地平线遮挡 / 窗口短于曝光 / 与已排目标冲突，逐目标说明
- **执行记录**：每目标实际起止时间 + 状态（完成/部分完成/跳过），重复提交自动覆盖
- **偏差分析**：开始偏差、结束偏差（相对计划，正=推迟、负=提前）、实际曝光分钟数；
  实际区间按该目标全部可见窗口逐段比对，输出越窗分钟数与越窗子区间（含跨翻转点间隙），
  「完成但实际时长不足曝光要求」标记为曝光不足
- **时间轴**：拖动平移、滚轮缩放；高度曲线 + 可见窗口 + 翻转点 + 计划/实际双甘特联动，
  点击图例/甘特条/表格行查看单个目标详情

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/samples` | 内置示例目标 |
| POST | `/api/plan` | 计算黑夜区间、各目标窗口/翻转点与不冲突观测序列，返回 `planKey` |
| POST | `/api/observations` | 提交（覆盖）执行记录，返回该计划全部记录与偏差汇总 |
| GET | `/api/observations?planKey=...` | 取回某计划已保存的执行记录与汇总 |

`POST /api/plan` 请求体示例：

```json
{
  "lat": 40, "lon": 116, "date": "2026-09-21",
  "minAlt": 25, "slewMin": 2, "flipMin": 5,
  "horizon": [0, 0, 0, "…共 72 个方位仓（每 5°）的遮挡角…"],
  "targets": [{ "name": "M31", "ra": "00:42:44", "dec": "+41:16:09", "expMin": 45 }]
}
```

`POST /api/observations` 请求体：在 `/api/plan` 的**同一组规划参数**之外附 `records` 数组；
服务端重算计划并按 **`planKey` + 目标 `index`** 匹配（也可用目标 `name`，重名时报错）。
`actualStart/actualEnd` 为 UTC 毫秒时间戳；同一目标在数组中或在后续请求中重复出现时，
**以后一条为准**；状态传空字符串 `""` 表示删除该目标的记录。

```json
{
  "lat": 40, "lon": 116, "date": "2026-09-21",
  "minAlt": 25, "slewMin": 2, "flipMin": 5,
  "targets": [{ "name": "M31", "ra": "00:42:44", "dec": "+41:16:09", "expMin": 45 }],
  "records": [
    { "index": 0, "status": "done",    "actualStart": 1789993260000, "actualEnd": 1789995960000 },
    { "index": 1, "status": "partial", "actualStart": 1789996000000, "actualEnd": 1789997200000 },
    { "index": 2, "status": "skipped" }
  ]
}
```

每条返回记录含 `analysis`：`startOffsetMin/endOffsetMin`（相对计划偏差，分钟）、
`actualMin`（实际曝光分钟数）、`outsideMin` 与 `outsideIntervals`（越窗分钟数/子区间）、
`outsideWindow`、`underexposed/shortMin`（完成但欠曝及缺口分钟数）；
`summary` 含完成率、总/平均偏差、越窗与欠曝计数等汇总指标。

时间显示为**地方平时**（UTC + 经度/15），接口返回均为 UTC 毫秒时间戳。
