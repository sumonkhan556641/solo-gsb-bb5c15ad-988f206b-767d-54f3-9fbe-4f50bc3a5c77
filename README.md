# 🔭 望远镜夜间序列规划台

使用 **Node.js + Express + 原生前端（Canvas）** 实现的夜间观测序列规划工具。

录入观测点纬度/经度、日期、目标赤经赤纬、曝光时长与最低高度，并可绘制地平线遮挡角；
系统按恒星时逐分钟计算每个目标的连续可见窗口，在**跨子午线翻转、窗口重叠、转台换向耗时**
约束下生成不冲突的观测顺序；无法排入的目标会给出具体原因。

计划生成后，还可为每个目标**录入实际执行记录**（实际开始/结束时间与状态），系统自动计算
**开始/结束偏差、实际曝光分钟数**，并识别实际区间是否超出该目标的可见窗口、曝光是否达标，
在时间轴与结果表中叠加高亮，并汇总完成率与总偏差。

## 一键启动（Docker）

```bash
docker compose up --build
```

启动后用浏览器访问：**http://localhost:3000**

> 依赖安装（`npm install`）已包含在镜像构建中，示例目标随服务启动自动载入前端。

## 本地运行（可选）

```bash
npm install
npm start          # 访问 http://localhost:3000
```

## 功能说明

- **观测设置**：纬度/经度、日期、最低高度、转台耗时、换向（子午线翻转）耗时
- **地平线遮挡角**：画布上拖动绘制 0–360° 方位的遮挡轮廓，内置平坦/树林/山坡/圆顶预设
- **目标管理**：赤经支持 `HH:MM:SS` 或十进制小时，赤纬支持 `±DD:MM:SS` 或十进制度，逐目标曝光时长
- **窗口计算**：基于地方恒星时逐分钟判定 `高度 ≥ max(最低高度, 地平线遮挡角)` 的连续窗口，
  并在上中天处切分为「东升侧 / 西落侧」两段（翻转点 ◆）
- **序列调度**：最早窗口截止优先的贪心算法；相邻目标计转台耗时，叉臂换侧计换向耗时，
  单次曝光不跨越翻转点，保证序列互不冲突
- **失败原因**：高度不足 / 地平线遮挡 / 窗口短于曝光 / 与已排目标冲突，逐目标说明
- **时间轴**：拖动平移、滚轮缩放；高度曲线 + 可见窗口 + 翻转点 + 甘特图联动，
  点击图例/甘特条/表格行查看单个目标详情

### 执行记录与偏差分析

1. 点击「生成观测序列」得到计划；
2. 在页面底部「执行记录与偏差分析」表中逐目标选择状态（**完成 / 部分完成 / 跳过**）并填写
   实际开始、结束时间（按**地方平时**录入，选择「跳过」时无需填时间）；
   也可点「用计划时间填充已排目标」一键带入计划时间；
3. 点击「提交执行记录」，记录发送至 `POST /api/observations`：
   - 后端按**目标下标 / 计划序号 / 目标名**将记录匹配到目标与计划序列；
   - 计算**开始偏差、结束偏差**（相对计划开始/结束，正=延后、负=提前，分钟）、
     **实际曝光分钟数**；
   - 将实际区间与该目标全部可见窗口求交集，识别**窗口外时长**；实际曝光短于计划曝光时标记
     **曝光不足**；
   - **同一目标重复提交时以后一次记录覆盖**（记录保存在服务端内存中，按观测计划签名归档，
     最多保留最近 200 个计划）。
4. 叠加展示：
   - 时间轴新增「实际执行」泳道：窗内实色、窗口外片段红色，部分完成 ◐、跳过 ⏭ 虚框、
     曝光不足加橙色边框；高度曲线上同步叠加绿/红实际区间；
   - 结果表中窗口外整行标红、曝光不足标橙，并列出偏差分钟数；
   - 顶部汇总**完成率**（完成目标数 / 全部目标数）、记录数、窗口外/曝光不足条数、
     实际总曝光/计划总曝光、**总绝对偏差**（开始偏差与结束偏差绝对值之和）。

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/samples` | 内置示例目标 |
| POST | `/api/plan` | 计算黑夜区间、各目标窗口/翻转点与不冲突观测序列 |
| POST | `/api/observations` | 提交/覆盖执行记录，返回逐目标偏差分析与汇总 |

`POST /api/plan` 请求体示例：

```json
{
  "lat": 40, "lon": 116, "date": "2026-09-21",
  "minAlt": 25, "slewMin": 2, "flipMin": 5,
  "horizon": [0, 0, 0, "…共 72 个方位仓（每 5°）的遮挡角…"],
  "targets": [{ "name": "M31", "ra": "00:42:44", "dec": "+41:16:09", "expMin": 45 }]
}
```

`POST /api/observations` 请求体在上述字段之外增加 `observations` 数组；
目标可用 `index`（目标下标）、`seq`（1 基计划序号）或 `name`（唯一时）匹配：

```json
{
  "lat": 40, "lon": 116, "date": "2026-09-21",
  "minAlt": 25, "slewMin": 2, "flipMin": 5,
  "targets": [{ "name": "M31", "ra": "00:42:44", "dec": "+41:16:09", "expMin": 45 }],
  "observations": [
    { "index": 0, "status": "completed", "actualStart": 1789991820000, "actualEnd": 1789994520000 },
    { "seq": 2, "status": "partial", "actualStart": "2026-09-22T02:26:00+08:00", "actualEnd": "2026-09-22T02:46:00+08:00" },
    { "name": "M27 哑铃星云", "status": "skipped" }
  ]
}
```

时间戳接受 UTC 毫秒数或 ISO 8601 字符串。响应中每条记录包含
`startDevMin` / `endDevMin` / `actualMin` / `outOfWindow` / `outsideMin` / `underexposed` 等字段，
`summary` 给出完成率与总偏差。未排入计划的目标也可录入记录（其偏差为 `null`，仅判定窗口/曝光）。
`observations` 传空数组则只查询该计划下已保存的记录。

时间显示为**地方平时**（UTC + 经度/15），接口返回的时间戳均为 UTC 毫秒。
